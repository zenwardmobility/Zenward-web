9. SERVICE PRESELECTION
======================================================================
Service pages link to /request-transportation?service=<value>. Explicit map (not
"any enum"): medical_appointment, dialysis, rehabilitation, hospital_discharge,

13. VALIDATION RULES (server-side; src/lib/request-intake/recurring.ts + actions.ts)
======================================================================
serviceType: exactly one of the 8 values; missing or unknown -> rejected (never
coerced to "other"). recurringSchedule: absent/null = one-time; otherwise a plain
object with ONLY the five known keys (unknown key, array, string, number, prototype
key -> reject). daysOfWeek: array of 1-7, lowercase weekday names only, no
duplicates (returned in Mon->Sun order). startDate: required, real YYYY-MM-DD
(2026-02-30 and 2026-13-01 rejected). endDate: optional ("" = absent), real date,
not before startDate (equal is allowed). appointmentTime: optional, 24-hour HH:MM.
returnTripExpected: optional strict boolean ("true"/1 rejected). Payload cap 16 KB
unchanged. Invalid schedule -> "Please check the recurring schedule…" message.
The validator is pure (no I/O or logging) and returns a fresh object.
