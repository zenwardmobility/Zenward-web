2. CONTACT RESULT CONTRACT — BEFORE / AFTER
================================================================================

BEFORE:
  interface ContactMessageResult {
    ok: boolean;
    referenceId?: string;
    error?: string;
  }
  - No signal of whether anything was actually delivered.
  - ContactForm showed "Message received / our team will get back to you"
    unconditionally whenever ok === true — untrue in stub mode.

AFTER:
  interface ContactMessageResult {
    ok: boolean;
    referenceId?: string;
    error?: string;
    delivered: boolean;   // <-- new, REQUIRED
  }

  Truth table now enforced:

    Situation                                    ok      delivered   UI
    -------------------------------------------  ------  ----------  ------------------------
    Stub adapter (default / current prod)        true    false       "This message wasn't
                                                                     sent" + call CTA
    Email mode, all creds set, Resend 2xx        true    true        "Message received" +
                                                                     reference id
    Email mode, missing creds                    false   false       error alert + form kept
    Email mode, Resend non-2xx                   false   false       error alert + form kept
    Email mode, network error / 10s timeout      false   false       error alert + form kept
    Guard / payload / validation reject          false   false       error alert + form kept

  It is now structurally impossible for the contact UI to state that Zenward
  received a message unless a mail provider returned a 2xx.

  (This mirrors `TransportationRequestResult.delivered`, which already
   existed and is unchanged.)

4. EMAIL BEHAVIOUR  (CONTACT_INTAKE_MODE=email)
================================================================================

  Provider: Resend REST API (https://api.resend.com/emails), plain `fetch`,
  no SDK, no npm dependency. 10-second AbortSignal timeout.

  Requires ALL THREE server-only vars:
    CONTACT_INTAKE_EMAIL   — destination inbox (to)
    CONTACT_EMAIL_FROM     — verified Resend sender (from)
    CONTACT_EMAIL_API_KEY  — Resend API key (Bearer)

  Payload sent to Resend:
    from     = CONTACT_EMAIL_FROM
    to       = [CONTACT_INTAKE_EMAIL]
    reply_to = the submitter's (shape-validated) email
    subject  = "New Zenward Website Enquiry — <topic label>"
    text     = plain-text block: Reference, Topic, Name, Email, Phone?,
               Organization?, Message   (NO HTML — no injection surface)

  Outcomes:
    - Any missing var → console.error (names the missing vars, no PII) →
      { ok:false, delivered:false, "We couldn't send your message just now.
      Please try again, or call us." }
    - Resend responds 2xx → { ok:true, referenceId:"ZW-MSG-…",
      delivered:true } → visitor sees "Message received / Our team will get
      back to you" + reference id.
    - Resend responds non-2xx → console.error(`… responded <status>.`) →
      { ok:false, delivered:false, <same error string> }.
    - fetch throws / times out → console.error("… email send failed.",
      err.name) → { ok:false, delivered:false, <same error string> }.

  FAILS CLOSED in every failure case: it never returns delivered:true, and
  never returns ok:true, unless Resend confirmed acceptance.

  NOT in this phase (see §10 / ZW-WEB-02C): retry on transient failure, a
  durable backup copy of a failed enquiry, rate limiting.
