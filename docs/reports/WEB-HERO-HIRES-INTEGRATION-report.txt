4. WHETHER THE FILENAME CHANGED FOR CACHE SAFETY
================================================================================

YES — deliberately.

The production site is already deployed on Vercel. Overwriting an existing
public URL is not a reliable way to guarantee the new asset everywhere. A new
canonical filename was created so the next deploy produces an unambiguous new
asset URL:

    zenward-hero-ramp-assist-v2.jpg

Next.js additionally content-hashes the static import, so the actual served
path is /_next/static/media/zenward-hero-ramp-assist-v2.<hash>.jpg — a fresh
URL that cannot collide with any cached copy of the old file.

No arbitrary query-string cache-busting was added anywhere in the UI.

the q82 4:2:0 used for supporting images — full chroma keeps the on-van text
("Zenward Mobility", "470-206-8005") and the ramp's perforated-metal edges
crisp. Quality was prioritised over the small bandwidth saving, as instructed.

9. GRADIENT CHANGES
================================================================================

The approved 3-layer architecture is unchanged and now explicit in the code
comments:
    Layer 1  sharp photograph (next/image fill) — no filter / transform /
             opacity applied here or anywhere in the tree
    Layer 2  Care Navy -> transparent gradient scrim (its own absolutely-
             positioned <div>; never touches the photo)
    Layer 3  headline / copy / CTAs (SectionContainer)

The previous scrim made the photo look hazy. It was lightened:

  Desktop (horizontal), before:
    NAVY 0% -> mix92 30% -> mix58 52% -> mix20 72% -> mix0 100%
  Desktop, after:
    NAVY 0% -> NAVY 19% -> mix82 34% -> mix44 52% -> mix12 70% -> mix0 86%
      - Solid navy is held across the far-left column (0-19%). This gives the
        headline a clean field AND fully covers the background "Dental
        Hospital" signage without touching object-position.
      - The mid/right values are lower (mix44 vs mix58, mix12 vs mix20), so
        the staff face, passenger, van, ramp, and branding read clearly.
      - The fade completes at 86%, so the far-right edge is fully un-tinted.

  Mobile / tablet (vertical), before:
    mix86 0% -> mix54 40% -> mix66 70% -> mix95 100%
  Mobile / tablet, after:
    mix82 0% -> mix38 36% -> mix50 66% -> mix92 100%
      - Lighter through the middle; still strong at top and bottom for text.

(mixNN = color-mix(in srgb, Care Navy NN%, transparent).)

Unchanged: the subtle Route Teal lower-left radial (brand character) and the
short bottom fade into the section below. No hard "dark panel | image panel"
boundary — the desktop left-to-right dissolve is preserved and premium.

10. DESKTOP OBJECT-POSITION
================================================================================

    lg:object-[56%_50%]   (was 68% 58%, tuned for the old 1:1 file)

Re-tuned for the new 1.792:1 source. On a wide hero, object-cover shows the
full image width and crops top/bottom; 50% vertical keeps the faces and the
ramp both in frame while trimming excess foreground road. 56% horizontal
centres the composition slightly toward the people.

Desktop priorities check:
    1. passenger clearly visible          - yes
    2. staff member clearly visible       - yes (full body, face clear)
    3. vehicle visible                    - yes (van fills the centre-left)
    4. ramp / accessibility context       - yes (deployed ramp prominent)
    5. dark left area behind text         - yes (solid-navy scrim column)


================================================================================
11. MOBILE OBJECT-POSITION
================================================================================

    object-[74%_42%]   (base; applies at <=1023px, i.e. mobile + tablet)

A portrait hero crops the 16:9 source hard on the sides, so the horizontal
value was pushed to 74% to keep the staff member AND the passenger in frame
(at ~64-90% of the source width); 42% vertical lifts the faces toward the top
of the copy block. The ramp remains prominent in the lower half.

At 390px: staff (torso + face above the paragraph), passenger (head/shoulder
+ the hand being held + rollator), ramp foreground, van door/rear. The
"Dental Hospital" sign is cropped out entirely.
At 768px (tablet): the full scene is visible and vivid — the strongest view.


================================================================================
12. LARGE-SCREEN SHARPNESS ASSESSMENT
================================================================================

Inspected at 1280, 1440, and 1920 (each at deviceScaleFactor 2, i.e. captured
at 2560 / 2880 / 3840 device px).

Result: a clear improvement over the previous hero. Faces, the polo-shirt
fabric, the passenger's knit cardigan, van body panels and door handle, the
ramp's perforated surface, the shrubs, and the building mullions all show real
detail. The gradient no longer washes the photograph — the right half is
crisp and vivid.

Honest limitation: the supplied source is 1376 px wide. On a standard-density
1440 or 1920 monitor the hero looks sharp. On a high-DPI / 4K / 5K desktop
display the browser enlarges the visible portion (roughly 2x), and mild
softness is visible under close inspection. This is a SOURCE-RESOLUTION
ceiling, not an implementation issue — the image is served at its native
maximum with no upscaling, at quality 90, in AVIF. Reaching the task's
2200-3000 px ideal would require a larger native hero photograph; the task
explicitly forbids upscaling to get there.

No pixelation, banding, blockiness, or compression artefacts were observed.
