REAL WEBSITE SUBMISSION — ATTEMPT 1 (2026-09-20): FAILED, ROOT CAUSE IDENTIFIED, STOPPED
======================================================================
Env vars set by the user; Production redeployed. From https://www.zenwardmobility.com/request-transportation
(real form, headless Chrome), ONE synthetic Recurring dialysis request was submitted: requester
"Zenward Website E2E QA", passenger PILOT-ZENWARD-WEBSITE-QA, Pickup/Destination "PILOT-ZENWARD-WEBSITE-QA
Pickup/Destination", Mon+Wed, 2026-10-05..2026-10-30, 09:15, return expected, synthetic notes.
(An earlier script run of mine was stopped by the browser's own required-field validation before any
request was sent — my automation had not switched the form to Recurring; nothing left the browser.)
RESULT: customer saw the calm copy "We couldn't submit your request. Please check the form and try
again, or call us..." — i.e. the adapter's `rejected` class (Nemryn generic 400). No technical detail was
exposed (customer-copy requirement holds). No Request was created: Nemryn Request Hub (org A "Siloan
Medical Centre", existing QA admin) still shows 0 pending after the attempt.

ROOT CAUSE (strong evidence, not directly observable — Nemryn returns one generic 400 by design):
Nemryn's RPC fails CLOSED when an integration has allowed_origins and the caller sends no Origin header
(submit_public_transportation_request, migration 20260919140000: `if p_origin is null or not (p_origin = any
(allowed_origins)) then raise`). A read-only CORS preflight shows an ACTIVE Nemryn integration is
origin-locked to https://www.zenwardmobility.com (OPTIONS with that Origin returns
access-control-allow-origin; a control origin does not). Zenward-Web's Server Action -> Nemryn call is
server-to-server, and the adapter sends NO Origin header, so it is rejected. The S4B-R1 production proofs
evidently supplied an Origin. Not ruled out (would look identical): wrong/disabled integration id in Vercel.

OWNER DECISION: Option A. Fix applied in the follow-up commit (adapter sends `Origin`, header only; default
https://www.zenwardmobility.com, optional server-only PLATFORM_INTAKE_ORIGIN; payload/contract unchanged; no
Nemryn change; test added). The options considered were:
  A. Adapter adds `Origin: https://www.zenwardmobility.com` on the server-to-server POST (header only;
     payload unchanged; from a server-side constant/env). Nemryn documents p_origin as a secondary,
     non-authoritative signal; Node fetch sends it (verified locally). Needs adapter change + test +
     commit + push + redeploy. No Nemryn change, no CORS weakening. RECOMMENDED.
  B. Nemryn-side: clear allowed_origins for this integration (production data change; removes the origin
     lock). Not recommended.
