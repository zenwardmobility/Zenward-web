integrationExternalId  <- env PLATFORM_INTAKE_INTEGRATION_ID (server-side)

passengerName          <- direct structured field

additionalNotes?       <- requester's own text, unchanged
serviceType            <- direct structured field
recurringSchedule?     <- direct structured object (omitted, never null, when one-time)

tripId/state/source can reach the wire (tested with a tampered input).

PASSENGER NAME     Sent as `passengerName`. No "Passenger: ..." folding. Also sent when
                   equal to requesterName (the old draft suppressed it).
SERVICE TYPE       Zenward SERVICE_TYPES == Nemryn SERVICE_TYPE_VALUES (8 values, identical;
                   asserted in a test). Sent directly, no transformation.
                   Product boundary: Nemryn accepting a value is not a public offering —
                   see OPEN ISSUES 1 (wheelchair_transportation).
RECURRING SCHEDULE Sent as {daysOfWeek,startDate,endDate?,appointmentTime?,returnTripExpected?}.
                   Requested intent only; Zenward-Web creates no Recurring Care records.

IDEMPOTENCY        One submissionId per logical submission (browser UUID on mount, kept across
                   failed attempts; Server Action re-validates/mints only if missing; adapter
                   never mints). Tests: retry re-sends the same key; new submission sends a new
                   key; exactly one HTTP attempt per submit().
NETWORK ARCHITECTURE  Browser -> Server Action -> adapter -> Nemryn HTTP. Server-to-server;
                   browser CORS is not the security boundary; Nemryn CORS not touched.
ENVIRONMENT        REQUEST_INTAKE_MODE (stub default | platform), PLATFORM_INTAKE_URL (https),
                   PLATFORM_INTAKE_INTEGRATION_ID (opaque id, not a credential). Nothing else.
                   No service-role key, anon key, DB credentials, admin token or Vercel token.
OBSOLETE TOKEN REMOVAL  No PLATFORM_INTAKE_TOKEN in code, .env.example, tests or the two
                   architecture docs (only the sentence saying it no longer exists).
                   Historical reports and docs/product/launch-readiness.md still mention it —
                   left as historical/unrelated (see OPEN ISSUES 3).
RESPONSE MAPPING   200 {"ok":true} -> delivered:true, "Request received", NO reference shown.
                   No Nemryn id is exposed or invented.
ERROR MAPPING      generic 400 / other 4xx -> "couldn't submit... check the form, try again, or call"
                   429 -> "receiving a lot of requests... try again in a little while, or call"
                   5xx / timeout / network -> "temporarily unavailable... please call"
                   2xx with body != {ok:true}, or non-JSON -> "couldn't submit just now... try again
                   shortly, or call" (delivered is never inferred)
                   Tests assert copy never contains nemryn/supabase/postgres/PGRST/ZW codes/
                   integration/rate-limit/status numbers/stack text.
MODES              stub (default/unknown value) -> safe stub, never calls fetch (tested).
                   platform -> real adapter; unconfigured or non-https -> fails closed, no fetch.
