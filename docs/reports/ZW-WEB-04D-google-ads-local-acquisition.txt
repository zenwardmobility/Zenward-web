11. INDEX / NOINDEX STRATEGY
----------------------------
  /locations/metro-atlanta   indexable, in sitemap
  campaign pages             <meta name="robots" content="noindex, follow">,
                             NOT in the sitemap, NOT blocked in robots.txt
                             (ads and users can reach them; links are
                             followed)
Why: campaign pages overlap the organic service pages and the hub. Noindex
prevents duplicate or cannibalising results; organic authority stays with
/services/* and /locations/metro-atlanta.

17. CONVERSION-EVENT ARCHITECTURE
---------------------------------
events.ts rewritten:
  - Conversion events: phone_cta_clicked {surface}, transportation_quote_
    started {}, transportation_quote_submitted {},
    provider_enquiry_submitted {}. Engagement events kept:
    request_transportation_clicked {source}, provider_cta_clicked
    {source}, contact_started {topic}. request_form_* removed.
  - sanitizeEvent(): rebuilds each event from a per-event key/value
    allowlist; unknown names or values -> dropped (null).
  - track(): sanitise -> registered sinks (each isolated in try/catch).
    NO sink is registered anywhere, so production is a no-op (dev console
    only).
  - registerAnalyticsSink(): the single future integration point (not used).
Documentation: docs/product/conversion-measurement.md.

19. PHONE-CLICK EVENT
---------------------
New client primitive TrackedPhoneLink (href always business.phoneHref)
fires phone_cta_clicked {surface} then lets the browser follow tel:. No
preventDefault, and track() never throws. Used by CallButton (now requires
`surface`), PhoneCtaButton (requires `surface`), both header modes,
footer, homepage band/inline/FAQ links, PracticalFacts (requires
`surface`) and ClosingCta (requires `surface`). Not converted (documented
gap): the request form's undelivered-success fallback tel: link and the
contact form's "message wasn't sent" tel: link, left unchanged to avoid
touching form internals.


20. QUOTE-START EVENT
---------------------
RequestTransportationForm: transportation_quote_started fires on the
form's first focus, guarded by the existing hasStarted ref (once per
mount), with no parameters. Page load does not fire it. Form behaviour is
unchanged.


21. QUOTE-SUCCESS EVENT
-----------------------
transportation_quote_submitted fires ONLY inside `if (result.ok)` ->
`if (result.delivered)`, i.e. Nemryn returned 200 {"ok":true}. It doesn't
fire on click, start, validation failure, delivery failure, the unlinked
fail-closed state (ok:false), malformed responses, or network errors.
There's no parameter, so hasReturnTrip was dropped. Test-enforced by
source position.


22. PROVIDER-ENQUIRY EVENT
--------------------------
ContactForm already returns `delivered` (true only after the email
provider's 2xx). provider_enquiry_submitted fires only when
`result.delivered && input.topic === "provider"`. No form content is sent,
and contact delivery is unchanged. Note: production contact delivery mode
(stub vs email) is still unverified (04A-exit), so in stub mode this event
never fires.
